# Projet 2 — Landing page produit avec un outil No-Code

**Cours de référence :** HTML - No Code
**Classe :** E1A
**Niveau :** Débutant
**Durée :** 1 semaine (PPE)
**Auteure :** Sofia Negreche

---

## 1. Contexte

Une startup veut tester rapidement l'intérêt pour un nouveau produit via une landing page, sans développeur.

## 2. Objectifs pédagogiques

- Utiliser un outil No-Code (Webflow, Wix, Carrd...) pour créer une page.
- Structurer un message marketing clair (accroche, bénéfices, appel à l'action).
- Publier la page en ligne.

## 3. Consignes / Étapes

1. Choisir un outil No-Code disponible.
2. Définir le message clé et l'appel à l'action.
3. Construire la page (structure + design).
4. Publier la page.
5. Documenter les choix effectués et limites de l'outil.

## 4. Livrables attendus

- Le lien de la landing page publiée (ou export HTML).
- Une note sur les choix marketing/design.
- Un avis critique sur les limites du No-Code.

# Livrable 2 : note sur les choix marketing et design

## 2.1 Choix de l'outil

J'ai choisi **Wix**. J'avais d'abord pensé à Carrd, plus simple, mais l'export du code HTML y est réservé aux comptes payants. Wix permet de publier gratuitement un lien en `.wixsite.com`, ce qui suffit pour le livrable.

## 2.2 Produit et cible

- **Entreprise :** éléctri'tek (électricien), le même univers que mon Projet 1.
- **Produit testé :** l'installation de borne de recharge pour voiture électrique à domicile.
- **Cible :** les propriétaires ou conducteurs de véhicules électriques qui veulent recharger chez eux.
- **Objectif de la page :** mesurer l'intérêt pour l'offre en récoltant des demandes d'éligibilité.

## 2.3 Message clé et accroche

- **Accroche :** « Rechargez chez vous. Partez toujours à 100 %. »
- **Sous-titre :** éléctri'tek installe votre borne de recharge à domicile, de l'étude à la mise en service.

L'accroche est courte et met en avant le bénéfice principal (recharger chez soi) plutôt que la technique.

## 2.4 Appel à l'action (CTA)

Le bouton principal est **« Tester mon éligibilité »**. Ce choix est volontaire : il est moins engageant qu'« Acheter », donc plus adapté pour tester l'intérêt d'un nouveau produit, et il invite le visiteur à laisser ses coordonnées.
![image](https://hackmd.io/_uploads/HyDNOt_TMx.png)


## 2.5 Structure de la page

1. **Accroche + bouton d'action** en haut de page.
2. **Trois bénéfices :**
   - Recharge ultra-rapide
   - Installation certifiée
   - Gestion via application
3. **Présentation de l'entreprise** pour créer la confiance.
4. **Témoignages clients** comme preuve sociale.
5. **FAQ** pour répondre aux doutes avant la prise de contact.
6. **Formulaire de contact** pour récolter les demandes.
![image](https://hackmd.io/_uploads/Hywoh2DTGx.png)


L'ordre suit un parcours simple : capter l'attention, convaincre, rassurer, puis faire agir.

## 2.6 Choix de design

- **Menu simplifié :** j'ai supprimé les liens « À propos » et « Projets » pour ne garder que l'essentiel. Une landing page doit rester sur une seule page, sans distraire le visiteur.
 ![image](https://hackmd.io/_uploads/SJganhv6Mg.png)
![image](https://hackmd.io/_uploads/rybAhnv6zl.png)


- **Nom de l'entreprise** en haut à gauche, à la place du logo du modèle (« Brand Name »).
- **Style sobre**, avec un bouton sombre bien visible pour l'appel à l'action.
- **Page d'accueil transformée** en landing page produit à partir d'un modèle.

> Remarque : les témoignages sont fictifs et servent uniquement à illustrer la structure de la page dans le cadre de cet exercice.

# Livrable 3 : avis critique sur les limites du No-Code

## 3.1 Ce que le No-Code a bien fait

- **Rapidité :** une page en ligne en quelques heures, sans écrire une ligne de code.
- **Modèles prêts à l'emploi :** structure et design de départ déjà corrects.
- **Publication simple :** un clic suffit, sans hébergement ni nom de domaine à configurer.
- **Fonctions intégrées :** formulaire, version mobile et hébergement sont fournis.

## 3.2 Limites rencontrées

- **Éléments inutiles dans les modèles :** le modèle contenait un panier, un logo « Brand Name » et un lien « Boutique » dont je n'avais pas besoin. Les supprimer a été plus compliqué que prévu.
- **Interface parfois cachée ou peu intuitive :** retrouver où modifier le menu ou supprimer une page m'a pris du temps, et les menus changent selon la version de l'éditeur.
- **Logo verrouillé :** je n'ai pas pu modifier le texte du logo directement, j'ai dû le supprimer et le remplacer.
- **Pas d'export du code HTML :** avec Wix, je ne peux pas récupérer mon site pour l'héberger ailleurs.
- **Version gratuite limitée :** adresse en `.wixsite.com` et options payantes pour le domaine personnalisé ou la messagerie professionnelle.

## 3.3 Comparaison avec le code (HTML/CSS)

| Critère | No-Code (Wix) | Code (HTML/CSS) |
|---|---|---|
| **Personnalisation** | Limitée aux options de l'éditeur | **Totale** : chaque détail est modifiable |
| **Contrôle du code** | Aucun accès au code source | Accès complet au code |
| **Propriété du site** | Dépend de la plateforme | Les fichiers m'appartiennent |
| **Export / portabilité** | Pas d'export HTML | Fichiers déplaçables n'importe où |
| **Performance** | Éléments inutiles chargés par le modèle | Page légère, uniquement ce dont j'ai besoin |
| **SEO** | Réglages prédéfinis | Contrôle fin des balises et de la structure |
| **Coût à long terme** | Abonnement pour les options avancées | Hébergement simple, souvent gratuit |
| **Versionnement** | Historique limité | Suivi précis avec Git/GitHub |
| **Fonctionnalités sur mesure** | Limitées aux applications proposées | Illimitées, avec JavaScript |
| **Vitesse de création** | **Très rapide** | Plus long, demande des compétences |
| **Courbe d'apprentissage** | Faible | Plus élevée |
| **Apprentissage technique** | On apprend l'outil, pas le web | On comprend vraiment comment fonctionne une page |

## 3.4 Conclusion

Le No-Code est idéal pour **tester rapidement une idée**, ce qui correspond exactement au contexte de la startup. Mais dès qu'on veut un résultat précis, un site léger ou un contrôle total, **le code reste beaucoup plus personnalisable**. J'ai vu la différence avec mon Projet 1, où je maîtrisais chaque élément en HTML et CSS, alors qu'avec Wix je dois composer avec les choix du modèle.

**Mon avis :** le No-Code pour valider vite une idée, le code pour construire un site durable et sur mesure.
